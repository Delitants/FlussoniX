# Native HTTP CDN admission

A FlussoniX load balancer reserves a CDN slot and an estimated stream bitrate before redirecting a viewer. The CDN independently authorizes the viewer, returns a clean playback URL, and keeps the promised slot while the viewer follows that redirect. A ticket grants no permission to watch a stream.

Unused tickets expire after five seconds. After a successful ticket redirect, the authorized session has five seconds to start its clean media request. Abandoned or revoked handoffs expire automatically and never start a worker or create recovery demand. Direct playback cannot take a slot held by an unexpired native HTTP reservation. Existing playback keeps its usual reconnect grace.

The CDN retains the estimated bandwidth cost through the redirect and media startup. Each tracked output has a byte counter sampled over the same interval as transport telemetry. Only the difference between its estimated bitrate and measured output remains reserved. This avoids charging measured traffic twice while retaining an estimate during output gaps. Activated segmented outputs with the same authorized session identity share their measured credit; pending tickets reserve their full cost independently. Segmented HLS and M4F credit follows the authorized session across control and media requests, expires after the existing 30-second reconnect grace, and is removed on revocation. A live M4F signal response also keeps its credit discoverable during longer segment pauses. The native node endpoint includes these temporary output credits in `reserved_mbps`; `reserved` still counts unredeemed tickets.

This mechanism applies to native HTTP/HTTPS ticket delivery. Vendor-backed HTTP and RTSP/SRT tickets keep their existing behavior. Admission estimates are not traffic shaping: direct viewers, cold bitrate estimates, and variable bitrate peaks can exceed a configured uplink. Current CPU, RAM and uplink checks still apply to every new cluster placement.
