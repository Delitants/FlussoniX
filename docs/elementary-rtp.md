# Elementary RTP with static SDP

Select **Elementary RTP (SDP)** in Streams or Templates for direct RTP or SRTP input and destinations. MPEG-TS/PT33 remains the default. Encrypted elementary uses key-free RTP/SAVP and owner-only key references; see [secure setup and session limits](elementary-srtp.md). SDP negotiation, SAP and WebRTC remain pending.

Input requires a literal, concrete IP URL `rtp://IP:PORT` or `srtp://IP:PORT` and an absolute **RTP input SDP file** reference. The file must be regular, owned by the daemon user, not writable by group/others, at most 16 KiB and not a symlink. No SDP JSON editing, inline credentials or remote descriptor fetching is needed. The descriptor's first connection and port must match the URL; all tracks use that IP, with distinct RTP ports and their consecutive RTCP ports. Port range is 1024–65520 at the URL. Reserve room through the base port plus 15 for up to eight tracks.

The static RTP/AVP or encrypted RTP/SAVP profile accepts one H.264 or single-layer HEVC video track and multiple AAC-LC, MPEG Layer II or MP3 audio tracks, including audio-only streams. There are at most eight tracks. H.264 uses packetization mode 1; HEVC uses single NAL, AP and FU without decoding-order negotiation. AAC uses indexed AAC-LC configuration, fixed 13/3/3 AU headers and noninterleaved complete AUs. MPEG audio uses the RFC 2250 four-byte header and 90 kHz clock. Dynamic types are 96–127; MPEG audio may use static PT14. Separate ports and SSRCs distinguish audio tracks with equal payload types. Unsupported codecs, attributes, cryptography and resource indirection are rejected.

Independent FFmpeg's AAC SDP emitter omits `streamtype`. The parser accepts that omission only after validating AAC-LC configuration and the fixed framing, then supplies audio streamtype 5 to the private decoder. See [FFmpeg's SDP emitter](https://github.com/FFmpeg/FFmpeg/blob/n7.1.1/libavformat/sdp.c) and [RFC 3640](https://www.rfc-editor.org/rfc/rfc3640).

Native sockets validate bounded codec payloads before pinning a media address and SSRC. An optional exact source IP filter and the existing 64-packet jitter/reorder window apply per track. Plaintext RTP source pinning is not cryptographic authentication. IPv4 multicast needs an explicit interface; group-specific binds isolate groups sharing ports. IPv6 unicast is supported, IPv6 multicast is pending.

The worker receives a regenerated SDP containing only validated codec parameters and owned loopback decoder ports. FFmpeg never receives the original addresses, file reference, arbitrary protocol attributes or public sockets. Before admitting public RTP or RTCP, managed worker startup verifies that every exact loopback RTP/RTCP port belongs to that worker's decoder PID, excluding the released handoff reservation inodes. Port occupancy by another process cannot make it ready. Decoder startup, relay writes and teardown are bounded. Input diagnostics retain the specific static startup/relay failure without exposing SDP paths or key material. This uses the same trusted daemon-host loopback boundary as other private worker bridges. RTCP sender reports reach the private decoder only after matching a pinned media peer and SSRC; valid receiver feedback returns only to that peer's consecutive port.

Each of up to four destinations uses the shared worker's native packetizer, with one RTP/RTCP pair per actual track at base + 2 × track index. There is no per-destination encoder. Random session timestamp origins preserve relative spacing. Native reconstruction keeps full AAC/MPEG sample duration through source-clock overlaps of at most 250 ms and preserves forward gaps; larger overlap fails the generation. See [the audio clock contract](worker-output-ts.md). Related tracks share one RTCP CNAME and a stable media/wall clock mapping, retaining presentation offsets despite send delays. Enabled destinations on the same IP must have non-overlapping reserved ranges (16 ports for elementary, two for MP2T); disabled rows and distinct groups can reuse ports. Rate pacing, datagram bounds, queue-lag detection, cancellation and codec-generation fences apply. Direct RTP/RTCP bytes and IP/UDP overhead contribute to existing uplink telemetry. Kernel sends are not delivery acknowledgements. A receiver-port ICMP refusal is counted as `unreachable_packets`; it does not stop the source or prevent downloading SDP for a late receiver. Other socket errors and queue lag fail the destination visibly.

After active media starts, use **Output → View SDP / Download SDP**. Authenticated GET `/flussonix/api/v1/rtp-sdp/STREAM?destination=0` returns `application/sdp` with `Cache-Control: no-store`. Indices are 0–3. This read does not start a source. Disabled, inactive, changed-target or superseded codec descriptions return conflict instead of stale SDP. A receiver must reload SDP after a worker or codec change. The UI discards descriptions when the worker/generation changes.

For an independent FFmpeg receiver, allow the file/UDP/RTP protocols and open the downloaded SDP. Copy-only remuxing of RTP audio requires `-copyinkf:a`, since depacketizers can omit audio key flags:

```sh
ffmpeg -protocol_whitelist file,udp,rtp -f sdp -i receiver.sdp \
  -map 0 -c copy -copyinkf:a -f mpegts received.ts
```

CPU-transcoded outputs use the same worker path. Internal VAAPI H.264 is opt-in qualified on the available iGPU; hardware HEVC is not qualified on this host. Separate DVB/teletext subtitle tracks need MPEG-TS carriage rather than this AV elementary profile. Embedded CEA carriage follows the existing copy/processing path but this first elementary matrix does not qualify its subtitle combinations.

Qualification uses independent FFmpeg senders and SDP receivers, exact codec/frame checks and strict decode: H.264 and HEVC paired with AAC/MP2/MP3, AAC audio-only, distinct MP2+MP3 tracks, and actual CPU video/audio conversion. Native tests cover malformed/foreign admission, reorder, RTCP, authenticated SDP, zero media epoch, late receivers, stale target/generation, shared workers and reaping. These small localhost fixtures do not establish WAN, sustained throughput or a complete Flussonic direction matrix.

## Investigating intermittent media loss

The independent elementary fixtures can retain private evidence with
`FLUSSONIX_ELEMENTARY_ARTIFACT_DIR=/absolute/owned/directory cargo test --locked --test elementary_media --test elementary_srtp_media -- --test-threads=1`.
Use a new empty directory for each run. Each codec case reserves a new private directory before evidence collection or media startup. Existing case paths, including empty directories and symlinks, are rejected with an instruction to choose another artifact directory. Previous evidence and caller files are left untouched.
This option changes only the test harness; it does not enable server-side packet logging or change socket buffers.

Each case records `boundary-evidence.jsonl` before sender startup and throughout delivery, including fixture stages, native worker statistics, process identity, host I/O pressure, observation/write durations, and the watched processes' owned IPv4 UDP sockets. Socket records include local/remote ports, inode, queue sizes and cumulative kernel receive drops. The sender, native test process, worker and independent receiver have separate roles. Ownership is checked using descriptor inodes and process start time; a missing observation is explicitly unavailable, rather than a zero drop measurement. A background thread owns collection and writes. Fixture notifications use a bounded nonblocking queue; queue delays and dropped notifications are explicit, and the final fixture stage is retained separately from queued events. Sampling occurs approximately every 100 ms for at most 60 seconds, with an 8 MiB evidence limit that reserves space for a minimal final stage/failure record. Descriptor races are marked partial. Other simultaneously running tests can own sockets in the same native test process, so use the serial invocation above and correlate ports rather than assuming every row belongs to an input lane.

A positive drop count identifies a socket that discarded incoming datagrams. A successful send, zero observed drops, or a passing rerun does not prove end-to-end delivery: a short-lived socket may close between samples, losses can occur elsewhere, and observation itself can affect scheduling. Additional packet capture may still be needed to locate missing HEVC pictures. An experimental synchronous collector reproduced HEVC/MP2 missing pictures with 56 kernel drops on the public video input, matching 56 native sequence losses. A later HEVC/MP3 repeat recorded 295 public input drops and a 6.66-second evidence write. That collector could itself block fixture stage notifications during disk stalls, so these reproductions cannot establish the cause of production loss. A real blocked-FIFO regression detects that observer defect, and the final collector uses nonblocking notifications. Offline comparison of the archived older HEVC/MP3 failure confirmed the same 38-picture gap in the worker recording and native RTP output. Its matching snapshot reports 91 aggregate input reorder gaps; an earlier zero-loss note conflicts with that archive. These are missing sequence positions across input lanes, not a video-specific kernel-drop measurement. The loss cause and the older HEVC/MP2 startup failure remain unresolved. These diagnostics are not a media-loss repair.

On success or assertion unwinding, the guard attempts to retain the available sender/receiver logs, sanitized SDP and worker/receiver recordings. Inline SDP crypto attributes and key files are excluded; these fixtures use synthetic media and a fixed test key. Case directories are owner-only and retained files are owner-readable/writable. Log/SDP retention is limited to 1 MiB per file and each recording to 64 MiB. CI enables this evidence collection for Rust qualification and uploads the owned directory only on Rust failure, with three-day retention. Output datagram evidence is buffered up to 4 MiB per lane during delivery and saved by the observer after the worker stops; overflow fails the fixture. Worker logs pass through the same capped retention helper. Shutdown waits at most two seconds for the observer. A timeout reports the observer operation, its elapsed milliseconds, the latest fixture stage and timeout status using in-memory metadata; operation labels are fixed and include no private paths or stream configuration. The metadata lock is never held during observation or filesystem I/O. This identifies where the observer was delayed, without establishing why it stalled or attributing a media failure to that delay. A timeout fails a normal fixture explicitly; during assertion unwinding it reports incomplete evidence without replacing the original failure. A blocked observer may remain detached until its filesystem operation completes or the test process exits; it owns no media child and retains only a weak worker reference. Missing terminal records and `incomplete` markers must be treated as incomplete observations. Oversized retained files are skipped and reported. The artifacts must never be populated from operator streams or production keys.
