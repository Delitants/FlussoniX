# DVB bitmap OCR qualification

This preview converts configured composition pages to selectable plain-text HLS WebVTT. It uses independently authored Rust bitmap decoding and an optional external Tesseract executable. It does not load official Flussonic components or decoder code.

Owned fixtures use DejaVu Sans English `EUROPE DVB`, German `GRÜSSE`, and `LIVE <&>`. FFmpeg renders the test glyphs; our fixture builder encodes transparent/white interlaced 8-bit bitmap objects in authored DVB PES/descriptor data alongside generated H.264/AAC video/audio. Literal tests separately exercise every 2/4/8-bit RLE branch, default/custom mapping, full/reduced palettes, ancillary ownership, updates, timeout and bounded corruption handling. Reconstructed German glyph pixels must match the independently rendered binary mask exactly. No production media or vendor runtime is required.

Copy and CPU encoding preserve original DVB language descriptors and five complete PES payloads while both TS and fMP4 HLS publish isolated English/German WebVTT. Source update/clear timing is checked exactly (`2.160–3.000` in the second segment); silence emits empty VTT. Original-track policy remains separate from HLS conversion. Grouped stream masters, rendition playlists and assets use viewer authorization, token propagation and immediate revocation. Mixed DVB/teletext delivery shares one private source copy without text leakage; existing analog/digital caption suites remain required.

Real Tesseract recognition qualifies English and German text, Unicode and confidence. A local German probe scored 96.6 and took 519 ms under concurrent Rust qualification load. The fixed queue-plus-process budget is 1.5 seconds; confidence below 60 suppresses the interval. Missing executable/model, stalled or oversized subprocesses are explicit failures. Fault-process tests check bounded output, cancellation, kill/reap and video progress in both variants with copy/CPU encoding. These cases qualify failure handling, not OCR accuracy.

OCR workers now wait for broadcast store changes and actual pending deadlines instead of polling every20ms. An owned100-state/200-worker waker probe checks zero idle timer wakeups over120ms, immediate notification of a real transport image, clock-reset cancellation with actual child reaping, and deadline expiry without source traffic. These are scheduler regressions, not a production throughput or soak measurement. Two workers, two daemon-wide processes and all existing job/interval/deadline limits remain unchanged; the separate100ms HLS playlist watcher still polls.

The measured native profile is coding-method-zero interlaced bitmap objects with SDR luminance/alpha, page/region/object/palette caches, display sets and source timeouts. Each page render allows at most 4 MiB of encoded bytes across all object replays and 4,194,304 painted pixels; mapping tables and empty strings consume the encoded-work budget too. Invalid row progression is rejected before further decoding. Character/progressive/compressed objects, HDR palettes and disparity degrade affected conversion. Color, placement and styling become plain text. Recognition quality depends on glyphs, resolution and installed models. Automatic service discovery, GPU conversion, real HEVC browser output, arbitrary programs/multisection PSI, regional native subtitle relay and capacity/soak tests remain pending.

Optional deployment packages on Debian/Ubuntu: `tesseract-ocr`, and each chosen language model, for example `tesseract-ocr-eng` and `tesseract-ocr-deu`. `FLUSSONIX_TESSERACT` may select a trusted executable at daemon startup. It is not a stream-controlled path. Qualification additionally needs `fonts-dejavu-core`. The server continues other subtitles and AV when OCR is unavailable. Inspect `hls_captions.dvb_pages` and `hls_captions.dvb_ocr` for announcement, model, pending jobs, confidence and failure reason.

The carriage definitions come from [ETSI EN 300 743](https://www.etsi.org/deliver/etsi_en/300700_300799/300743/01.06.01_60/en_300743v010601p.pdf); the independent subprocess interface follows [Tesseract CLI/TSV documentation](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html).
