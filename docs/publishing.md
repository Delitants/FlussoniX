# HTTP MPEG-TS publication preview

v0.9 adds static configured publication. Create a stream or template with the normal **Input mode → Receive a publication** selector. The API input is exactly `publish://` as its sole input. Templates inherit that input and optional publisher password/callback; editing another setting preserves inherited values. Publisher password fields and settings summaries are masked. Templates explain how to create an inheriting stream; the stream form displays its own publication URL, including inherited receive mode. Private cluster discovery sends only playback policy, display metadata and media identity; publisher passwords, callbacks, upstream inputs and raw saved configuration are excluded.

An enabled local stream on a standalone/source/CDN node accepts `POST /{name}/mpegts`. Use MPEG-TS bytes with no content type, `video/mp2t`, or `application/octet-stream`. A `password` query parameter must match the stream/template `password` if configured; `token` goes to the callback. Viewer, management and peer credentials do not bypass these checks. The LB does not accept publications or discover dynamic published names. The v0.10 native HTTPS listener serves this POST handler with the same policy; see [HTTPS delivery](https-delivery.md). RTSPS playback remains separate and does not imply RTSP publication.

`on_publish` supports an absolute HTTP(S) URL or `auth://backend` resolving a configured auth backend. Only string policies are accepted. The backend receives POST JSON with name, proto=mpegts, socket IP, token, original qs, user_agent, referer, host, stable UUID session_id, request_type/new_session or update_session, request_number starting0, stream/total viewer counts, duration and cumulative received bytes. Only 200 permits streaming. Redirects are not followed; callback requests use no environment proxy and a three-second deadline. X-AuthDuration must be1..3600 seconds (default30); invalid durations, denial or outage on renewal terminate the publication. No publisher callback body/ad policy, X-UserId/global user limits, X-Max-Sessions, denial cache/history or publisher session API is claimed. Existing viewer sessions continue to use their independent policy and endpoints.

Publication starts no worker until credentials/callback pass. Exactly one publisher owns a stream under the media-map admission fence. Another publisher gets409; reader/reconciliation requests reuse an active worker and never start an empty publication. Initial checks, startup fences and250ms checks reject changed effective publisher/media policies; metadata-only edits retain the connection. Changes while a callback is pending are checked too. Disabling/deleting a stream/template, disconnect, request cancellation, a stopped worker or shutdown cancels that exact generation and reaps FFmpeg. Reconnect can start immediately without pull backoff. Waiting publications are not idle-retired or restarted by the pull supervisor.

Uploads are streamed with pipe backpressure; no total2MiB management-size limit applies. Slices forwarded to FFmpeg are at most64KiB, with at most one partial188-byte TS packet retained. Sync/alignment are checked; empty/truncated/invalid bodies return400. A body/media/progress timeout uses `flussonix_input_timeout` (1..300 seconds, default15), and EOF draining is bounded to three seconds before204 when media was produced. Callback renewal can briefly pause reading under normal network backpressure. The node allows64 pending/active publication requests and at most256 live workers. Query limit16KiB, metadata fields4KiB, password/token1KiB; repeated credential parameters are rejected. Packet synchronization is framing validation, not a full transport-stream conformance or codec validator.

Independent FFmpeg consumes pipe-only MPEG-TS and produces the shared output pipeline. Input probing is 1 MiB/one second. CPU processing encodes once; copy publication maps all audio tracks. The [live worker TS bridge](worker-ts-live.md) originates native AVC/HEVC, AAC and MPEG Layer II/III from the same encoded AV transport. AV-only stdout is decoded directly; preserving original subtitle tracks uses a worker-owned AV-only MPEG-TS tee connection. Diagnostic stderr is drained separately. Optional fMP4 copy packaging failure cannot stop supported TS/native outputs. Cancellation, malformed transport and either media channel closing end the generation and reap its child. No vendor executable, library or asset is required.

Tests independently decode both HLS variants with H.264/AAC in copy and CPU modes, exercise native private M4S/M4F source pulls, and verify the shared RTP packetizer. Existing RTSP/RTSPS playback can use that worker. GPU configuration is available but no GPU success is claimed without actual hardware testing. Full RTSP/SRT publication, outbound push, direct RTP/SRTP, dynamic templates, additional codecs, full vendor/session/API parity, sustained-scale and migration qualification remain later gates.

Reference contracts were read from the official [publishing guide](https://flussonic.com/doc/fms/live/publish/) and [authorization schema](https://flussonic.com/doc/api/authorization.json). Those describe a larger product; this document identifies the implemented subset. [FFmpeg stream-copy initialization](https://github.com/FFmpeg/FFmpeg/blob/n7.1.1/fftools/ffmpeg_mux_init.c) and [tee muxer](https://github.com/FFmpeg/FFmpeg/blob/n7.1.1/libavformat/tee.c) explain the container-tag handling underlying the copy-mux adapter.
