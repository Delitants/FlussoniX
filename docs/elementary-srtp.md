# Encrypted elementary RTP

Elementary input supports `srtp://IP:PORT` with `flussonix_rtp.profile=elementary`, an absolute `sdp_file` reference and an absolute `key_file` reference. The source SDP must use `RTP/SAVP` for every track; plaintext sources require `RTP/AVP`. The SDP contains codecs/addresses/ports only. Inline crypto attributes, key negotiation and transport mismatch are rejected. This is static out-of-band keying rather than SDES or DTLS negotiation. The native sockets use independent system libsrtp2 AES_CM_128_HMAC_SHA1_80; FFmpeg receives only authenticated plaintext on private owned loopback pairs.

The owner-only regular key file contains the base64 encoding of30 bytes (16-byte key and14-byte salt), without inline URL/JSON key material. The daemon loads one key snapshot before binding any public pair and creates separate per-track/direction contexts. Replacing a file affects the next transport generation, not an active context. Changing the configured key-file reference replaces the worker. Missing, unsafe or unsupported key/library initialization fails without public socket admission or plaintext fallback.

Authentication and replay protection precede codec validation and source/SSRC pinning. Configured source-IP filters run before crypto. Authenticated malformed pre-pin candidates preserve replay/rollover history while relinquishing ownership. Alternate SSRCs are authenticated before prior candidate state is retired; invalid tags cannot reset it. Valid full-size1600-byte media packets include the10-byte authentication trailer on public ingress. Related same-payload audio tracks retain independent contexts. SRs are decrypted before the decoder receives them; valid private decoder feedback is encrypted before returning to the pinned public source's consecutive RTCP port. Structural admission is not a complete bitstream decoder; private loopback assumes a trusted daemon host.

Existing sessions cross sequence rollover. A receiver starting against a source already beyond the first rollover needs a coordinated fresh sender epoch; automatic ROC transfer, transparent migration into an established later epoch and automatic rekeying are not implemented. Use source-specific keys and source SSRCs distinct among tracks sharing a key. Output uses random 32-bit SSRCs with collision checks among its related lanes; it has no persistent global identity registry across daemon restarts. Coordinate key rotation for extensively reused static keys; fresh randomness does not prove lifetime nonce uniqueness. A configured source/key holder remains responsible for its sender epoch and nonce discipline.

The owned qualification uses independent FFmpeg SRTP senders: H264/HEVC with AAC/MP2/MP3, AAC-only, distinct MPEG audio tracks and actual CPU HEVC/MP3 processing. Strict independent elementary output decode verifies codecs and frame counts. The harness also records shared MPEG-TS playback, but its separate independent decode qualification remains pending. Wire fixtures check tamper/replay/wrong key/plaintext/foreign rejection, malformed-before-pin rollover, encrypted SRTCP feedback, key snapshots, cancellation and socket release. WAN, throughput, maximum capacity and full migration parity are not established by these small local tests.

FFmpeg emits a private source descriptor with inline SDES and AVP transport even for an encrypted output. For this out-of-band profile, configure a key-free descriptor by removing crypto lines and explicitly using SAVP, then supply the matching key through the owner-only file. The test harness performs this conversion only on its own generated descriptor; it never imports keys from arbitrary SDP. See [FFmpeg SRTP](https://ffmpeg.org/ffmpeg-protocols.html#srtp), [FFmpeg SDP parser](https://github.com/FFmpeg/FFmpeg/blob/n7.1.1/libavformat/rtsp.c), and [RFC4568](https://www.rfc-editor.org/rfc/rfc4568.html).

Select elementary for a `srtp://` destination and provide its labeled **SRTP key file** reference. Each destination/track gets a fresh random SSRC and a sequence starting at zero, independent of the shared worker packetizer. Related tracks retain one CNAME and media/wall mapping. RTP and sender reports are encrypted; receiver feedback is authenticated before pinning. Pacing and uplink accounting include encrypted trailers and IP/UDP overhead. Output preserves bounded queues, generation fences, cancellation and late receiver handling. There is no per-destination encoder.

**Output → View SDP / Download SDP** provides an authenticated, key-free `RTP/SAVP` descriptor after actual media starts. Configure the matching key locally on the receiver; the descriptor does not negotiate or export it. FFmpeg receivers require a private owner-only local descriptor with their own `a=crypto:1 AES_CM_128_HMAC_SHA1_80 inline:...` receiver configuration and the `file,udp,rtp,srtp` protocol whitelist. Never upload that private receiver descriptor as a FlussoniX input or serve it to viewers. Receiver copy-remuxing needs `-copyinkf:a` for RTP audio. Automatic SRTP key/epoch negotiation remains pending.

Streams/Templates keep the elementary profile and SDP reference when changing plaintext to encrypted URLs. Changing to plaintext clears key references; choosing MPEG-TS clears the input SDP reference. The key controls reference local files, and no editable JSON or raw keys are needed. Independent secure-to-secure receivers qualify H264/HEVC with AAC/MP2/MP3, audio-only/multiple tracks, CPU conversion and opt-in internal H264 VAAPI under a compatible independent driver. Hardware HEVC remains unqualified on this host. Existing encrypted MPEG-TS/SRTP is unaffected. Separate DVB/teletext subtitles use MPEG-TS; this audio/video elementary profile does not carry separate subtitle tracks.
