# HLS subtitle decisions and tradeoffs

Delivered: native selectable plain-text 608 WebVTT, explicit raw DVB/teletext TS-HLS pass-through, and HLS subtitle filtering with friendly inherited controls. Original-track policy on other outputs is independent. No official vendor runtime or caption executable is used.

One fresh-context whole-branch review found three Important issues: timestamp epochs, malformed caption reset, and regional TS-HLS loss. All were reproduced and fixed; final local checks pass304 Rust tests (one existing external opt-in ignored),22 browser cases, formatting, all-target warnings-denied Clippy and frontend build. No deferred minor findings. Tests qualify owned local sources and players, not a production migration or sustained scale.

The decisions below are recorded in execution order. The narrower pre-review embedded-only pass-through decision is superseded by the explicit raw TS-HLS decision. Every cost remains stated; additional regional conversion, fMP4 raw carriage and broader migration qualification are pending.

- Continue inline without repeated design/execution/publication permission menus — standing user authorization and developer autonomy instruction — cost if wrong: reversible feature branch and published follow-up changes.
- Implement native 608 first instead of integrating CCExtractor — pinned v0.96.6 probe produced mistimed 608/708 and empty 708 WebVTT; no external decoder dependency added — cost: teletext/708/OCR conversion remains pending.
- Reuse existing approved UI layout — this adds controls to established forms rather than redesigning product — cost: fewer visual alternatives.
- Capture the initial encoded clock from live TS, then derive fMP4 anchor using matching current TS/fMP4 segment video PTS — burst sources can slide/delete the initial HLS files before a watcher sees them — cost if wrong: subtitle synchronization offset; real copy/CPU tests qualify both variants.
- Emit stable one-second display slices and retain full overlapping slices — long visible captions have no known erase time when a segment is published, so whole mutable cue end times cause duplicate or truncated player cues — cost: more VTT cues and one held-back segment of latency.
- Explicit bounds include 512 caption pairs/AU, 64 pending presentation events/4096 pairs and 1 MiB VTT — malformed or unreasonable services cannot allocate indefinitely — cost: oversized caption access units fail conversion; AV remains available.
- target GA94 process/valid flags at HLS delivery, retaining byte lengths and unrelated SEI, rather than removing all SEI through FFmpeg filter_units (which would also remove HDR metadata). Cost: bounded per-request segment parsing for drop; unsupported framing fails closed. Other output original-track control stays independent. Standing approval authorizes this requested extension; no repeated gate.
- prepare UI while independent Task 2 qualification compiles, using the now-fixed mode/row interface — no shared implementation agent or concurrent edits — cost: browser qualification waits for latest owned daemon. Task 2 commit remains a separate gate before final completion.
- cancel the pending owned broad run when a new audio-only filter regression needs its focused RED first — preserves test-first evidence and avoids broad runs during known incomplete fixes — cost: interrupted final-rust log is not a passing qualification. A fresh complete final run is required after this fix.
- pass-through and filter are scoped to supported embedded GA94 captions on HLS; unsupported DVB/teletext renditions and native/global stripping stay explicit pending work — follows per-output original preservation contract — cost: filter-out on HLS does not remove originals from other protocols. Inactive original caption data is retained as length-preserving disabled SEI, not an encoded-data redaction guarantee. No migration/scale claim.
- explicit TS-HLS passthrough includes raw regional tracks; supersedes Task 3's narrower embedded-only scope — user explicitly requests original-format HLS and review verified missing PIDs — cost if wrong: a new generation-owned playlist/cleanup task and format-specific player support. Omitted defaults stay compatible; fMP4 limits stay explicit.
- full 708/teletext decoding and DVB OCR remain later stages — users get 608 WebVTT and raw TS regional preservation, with unsupported conversions stated — cost: those regional conversions are unavailable.
- raw DVB/teletext in fMP4 remains unsupported — controls specify TS-HLS carriage and no selectable regional text rendition — cost: fMP4 viewers cannot receive these original separate tracks.
- real HEVC-caption player delivery and GPU extraction remain unqualified — no such success claim is made; owned framing/filter tests are narrower — cost: these combinations still need hardware/player qualification.
- service discovery, native regional relay, migration aliases and sustained scale remain deferred — manual 608 channel selection and measured local behavior are the delivered subset — cost: broader migration and regional cluster workflows remain incomplete.
- HLS filtering is flag suppression, not encoded-data redaction/global stripping — inactive bytes and other-protocol originals remain by design — cost: it cannot satisfy a requirement to remove confidential caption bytes from every output.
- style and exact screen placement remain plain text — text and timing are delivered without complete legacy layout — cost: presentation can differ from original captions.
- valid silent input can retain displayed text until an erase — normal caption state is not timed out arbitrarily; malformed recognized data now resets it — cost: broken sources without erase may leave a valid open display.
- automatic decoder recovery after a generation-scoped fatal error stays deferred — AV continues and stats expose failure until worker replacement — cost: captions require replacement to recover from fatal decoder failures.
