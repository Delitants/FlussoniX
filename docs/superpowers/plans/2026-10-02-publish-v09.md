# HTTP MPEG-TS Publication v0.9 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Receive authenticated HTTP MPEG-TS publications into independent shared streaming workers.
**Architecture:** Bounded publisher policy/callback and streaming HTTP handler; worker-map fenced stdin admission; existing independent FFmpeg packaging and viewer/cluster outputs.
**Tech Stack:** Rust/Tokio/Axum, React, existing independent FFmpeg; no new dependencies.
**Spec:** docs/superpowers/specs/2026-10-02-publish-v09.md

## Global Constraints

Vendor components absent. Exact sole publish:// input; configured static local streams only. Publisher password/on_publish independent of viewers/peers. 64 publication permits; callbacks 3 seconds/no redirects/proxies; renewal default30/max3600 seconds/fail closed. Query16KiB/field4KiB/credential1KiB. Packet188 bytes/one partial; writes64KiB/default15secwatchdogs/250mspolicychecks/3secEOFdrain. One fenced worker per stream; cancellation touches exact generation; no idle publisher restart. Normal form fields/template inheritance. Standing authorization overrides redundant approval menus; inline implementation, one fresh final reviewer.

## Review Focus

- Rejected publishers and metadata must not consume body, allocate workers or bypass password with peer/viewer credentials.
- Concurrent callback/startup/config edits must not admit stale policies or cancel a replacement.
- Oversized streaming uploads, partial TS packets and slow senders must stay bounded and terminate correctly.
- Request drop, worker exit, shutdown and reconnect must release permits/stdin/children without global lock stalls.
- Template inheritance and independent viewer auth must survive publication mode changes and cluster discovery.
