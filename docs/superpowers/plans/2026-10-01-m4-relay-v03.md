# M4 relay v0.3 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve M4 source payloads and timeline while supporting packed GOP ingest and selected native LAN transports.
**Architecture:** Decode observed records in the wire adapter, relay immutable bytes through a byte-bounded shared hub, and package HLS/TS independently in the existing supervised worker. Source configuration chooses native transport explicitly.
**Tech Stack:** Rust/Tokio/Axum, existing FFmpeg worker, React admin; no new product dependencies.
**Spec:** docs/superpowers/specs/2026-10-01-m4-relay-v03.md

## Global Constraints

- Isolated worktree; inline execution under existing user authorization; production Flussonic untouched.
- AVC/AAC only; 16 MiB wire record, 32 MiB decoder buffer/bootstrap, 256 records / 16 MiB live queue, 8 / 64 MiB cached segments.
- No vendor runtime dependency, secrets/media/reference extracts in git or release.
- Preserve v0.2 auth, peer separation, generation fencing and default HLS cluster behavior.

## Review Focus

- Malformed nested boxes/NaN/duplicate track IDs must return errors without amplified allocations.
- Slow readers and large GOPs must not defeat byte limits or lose wakeups.
- Codec revisions/late join must not combine stale metadata with new media or start with video inter-frames.
- Source HTTP redirects must never send native peer credentials to a different host.
- Config/stop/source failures must cancel original wire delivery and reap packaging children.
