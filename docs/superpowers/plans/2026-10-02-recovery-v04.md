# Streaming recovery v0.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task inline.

**Goal:** Recover failed/stalled configured inputs and maintain decodable HLS restart behavior without another viewer request.

**Architecture:** Keep the existing serialized Engine lifecycle, shared worker and bounded media queues. A recovery helper records sanitized failure/backoff; ensure and recover share lifecycle but differ in demand accounting. Reconcile controls background recovery and config fences; HLS attempts receive new sequence/URI generations.

**Tech Stack:** Rust/Tokio/Axum, independent FFmpeg, React/Playwright, x86_64 musl.

**Spec:** docs/superpowers/specs/2026-10-02-recovery-v04.md

## Global Constraints

- Independent build/tests/runtime; installed Flussonic is reference only.
- Static retries indefinitely; on-demand demand grace 60 seconds, background retries never touch demand.
- Timeout extension 1..300 seconds, default 15; retry 1/2/4/8/16/30 seconds, cap 30, healthy reset after 30 seconds.
- One worker per stream, bounded queues, sanitized status, existing policy/source cancellation and revision fences.
- Same configured relationship only; no implicit new origin-equivalence or seamless continuous-connection migration.
- Preserve friendly forms, unused local port and isolated remote prefix/unit; production Flussonic unchanged.

## Review Focus

- Stop/disable/delete racing retry must not revive stale workers; pin to Task 2 with concurrent stale config regression.
- Fallback must retain peer credentials and config signature; no URL/key in telemetry; pin to Task 1 native timeout/fallback regression.
- Repeated background recovery must not keep inactive on-demand workers alive; pin to Task 2 preserved-demand/retirement regression.
- HLS media/init filenames must not identify different bytes after replacement; pin to Task 3 sequence/name/init/decode regression and real browser failure playback.
- Stalled output with an alive child and long-running successful output require opposite watchdog outcomes; pin to Task 1 owned blocked executable and healthy real FFmpeg regressions.
