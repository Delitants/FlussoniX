# Standalone HTTPS v0.10 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Serve the existing authorized stream and publication routes over independently implemented TLS.
**Architecture:** A bounded rustls Axum listener shares the existing router/app; socket ConnectInfo survives TLS. A listener-owned security marker controls HTTPS redirect rules; startup metadata feeds normal Config status.
**Tech Stack:** Rust/Tokio/Axum/rustls, React, independent FFmpeg; existing dependencies only.
**Spec:** docs/superpowers/specs/2026-10-02-https-v010.md

## Global Constraints

Vendor components absent; production ports/configuration unchanged. Optional HTTPS with required PEM paths and HTTPS-only mode. Validate/bind before workers. TLS1.2/1.3 HTTP/1.1;128 pending handshakes;five-second handshake/drain bounds. Preserve real socket IP; ignore spoofed forwarding/security headers. Same authorization and shared workers. HTTPS viewer redirects never downgrade. Normal read-only Config status; no exposed secrets. Codec qualification remains H.264/AAC.

## Review Focus

- Slow/malformed handshake flood cannot serialize valid clients or leak sockets on cancellation.
- HTTPS-only startup with bad key or busy port cannot bind plaintext or start workers.
- Forwarded headers cannot spoof callback identity or force TLS downgrade.
- Mixed CDN destinations and backend redirects must not leak HTTPS viewer credentials to HTTP.
- Streaming publication/disconnect and shutdown preserve existing worker fences/auth/accounting.
