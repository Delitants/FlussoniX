# SRT caller output implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan inline, task-by-task.

**Goal:** Deliver shared stream output to independent SRT caller destinations with encryption and friendly controls.

**Architecture:** Parse a strict v3 pushes subset into a private transport profile. Each enabled push consumes the worker's bounded broadcast through a supervised copy-only FFmpeg child; ownership stays inside the worker cancellation/join lifecycle. Local config alone activates pushes.

**Tech Stack:** Rust, Tokio, independent FFmpeg/libsrt, React, Playwright.

**Spec:** `docs/srt-push.md`

## Global Constraints

- Caller only; at most four destinations; exact limits and units in the spec.
- No official Flussonic runtime/build dependencies or production modifications.
- No plaintext fallback from encrypted output; no secret-bearing diagnostics.
- Inline implementation in an isolated worktree; fresh final review before publication.
- Full Rust/browser checks and exact candidate CI before main integration.

## Review Focus

- Raw `#!::` stream IDs must survive URL parsing; queries must not hide unknown options.
- An unreachable encrypted receiver must not block healthy output or playback.
- Cancellation during a stalled write must reap every copy process before worker completion.
- Templates, explicit empty pushes, disabled pushes and discovered CDN mirrors have distinct activation behavior.
- Runtime/UI diagnostics must not expose stream IDs, query credentials or FFmpeg errors.
