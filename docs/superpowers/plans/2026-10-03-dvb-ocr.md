# DVB OCR Implementation Plan

> Execute inline with superpowers:executing-plans and one fresh whole-branch reviewer. Standing user authorization covers isolated development, testing and publication without repeated approval handoffs.

**Goal:** Convert selected DVB bitmap services to authenticated selectable WebVTT without blocking AV.
**Architecture:** Native bounded bitmap state and shared subtitle transport feed interval records; asynchronous limited Tesseract jobs fill text before the existing HLS publication frontier freezes files.
**Tech stack:** Rust/Tokio, existing FFmpeg, optional Tesseract/model files, React/Playwright.
**Spec:** docs/superpowers/specs/2026-10-03-dvb-ocr.md
**Base:** dbee173e43f4287f11a0c052dfeb4f481446dbed
**Global constraints:** Four combined services; independent original-track policy; no vendor code/components; bounded caches/jobs/output;750ms OCR deadline/minconfidence60/two processes; original wire selectors/URLs preserved. Exact-head CI before FF main, restore49285, archive owned workspace/normal worktree removal.

## Review Focus
- Rebinding the same PID to a new ancillary/composition page must discard queued PES and recognition tokens. Task1/2 regression.
- Clear/timeout while OCR is pending must retain the original interval end and never resurrect stale text. Task2 regression.
- Malformed pixel runs/coordinates/cache churn must fail before unbounded work/allocation and preserve other services. Task1 regression.
- A stalled/oversized OCR process and queue pressure must resolve subtitle publication and keep both AV variants progressing. Task2 real-process/delivery regression.
- Multiple languages and mixed CEA/teletext/DVB must stay isolated through CPU copy, auth revocation, inheritance and browser playback. Task2/3 regression.
