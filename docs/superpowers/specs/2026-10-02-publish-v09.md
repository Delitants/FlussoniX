# HTTP MPEG-TS publication v0.9 design

Continue approved independent streaming development with static `publish://` input and authenticated `POST /{name}/mpegts` publication. Preserve existing playback, cluster private source pulls, TLS/RTSP and passthrough/CPU/NVIDIA configuration. No vendor runtime, source, assets or new product dependencies. This architectural receiving direction is implemented inline in an isolated worktree under standing development/test/publication authorization.

Reference contracts: [publishing guide](https://flussonic.com/doc/fms/live/publish/) and [authorization schema](https://flussonic.com/doc/api/authorization.json), read 2026-10-02. Stream/template `password` protects the publication via the query parameter; `on_publish` supports an absolute HTTP(S) URL or `auth://name`, independently of `on_play`. Initially support string policies only; reject unsupported publisher policy objects. `publish://` must be the sole input and exact URL. Dynamic prefix streams and mixed publish/pull inputs are deferred explicitly.

The HTTP handler admits only configured local enabled streams on non-LB nodes. Bound query/header metadata, reject ambiguous repeated password/token fields and content types other than absent, application/octet-stream or video/mp2t. Parse credentials before consuming the body. Constant-time password comparison; management/viewer/peer credentials confer no publisher bypass. Acquire a node-wide 64-request publication permit before awaiting callbacks. POST the documented JSON metadata (name, proto=mpegts, socket IP, token, original qs, user_agent, referer, host, stable UUID, new/update request count, client counts, duration and bytes). No redirects/proxies; three-second callback deadline; only 200 allows. Honor X-AuthDuration (1..3600, default 30 seconds) and renew with the same ID/count/incoming byte total; reject or outage on renewal ends publication. X-UserId/X-Max-Sessions, denial caching/history and full auth_spec are deferred and not parity claims.

A worker-map fenced admission admits exactly one publisher per stream; readers/reconciler only reuse an active worker, never create a waiting publication worker. Spawn independent FFmpeg with MPEG-TS stdin and protocol whitelist pipe only, preserving existing output/transcoding behavior. Retain exact-generation cancellation and takeable stdin in the worker; publication Drop cancels that worker without touching a replacement. No receiver media is accumulated: streaming body chunks are forwarded in slices at most 64 KiB with bounded pipe backpressure. Startup/media and body stall watchdogs use flussonix_input_timeout (default 15 seconds), pipe writes bounded by that deadline. No total publication byte limit, so uploads larger than management's 2 MiB limit work. Reject incomplete/non-188-byte-aligned transport input or invalid sync bytes; maintain at most one 188-byte partial packet. Limit callback metadata to 16 KiB query, 4 KiB fields and tokens/passwords to 1 KiB.

Recheck effective media and publisher policies after callback, under startup fence and every 250 ms during streaming; unrelated metadata saves do not interrupt sessions. Changed credentials, callback endpoint, disabled/deleted stream/template or media config terminate only the current publication. Cancel on request/task drop, disconnect, worker exit, timeout or daemon shutdown; reap FFmpeg via existing worker supervisor. Bounded EOF drain (three seconds) before 204; errors return 400/403/408/409/415/503 as appropriate. Completed/stalled publications leave waiting state; reconnect is immediate without pull retry backoff. Packet validation qualifies H.264/AAC-LC MPEG-TS in passthrough and CPU; other codecs rely on current independent packager, GPU remains hardware-unqualified.

Friendly Streams/Templates forms provide pull versus publication input mode, masked publisher password and publication callback selector/backend/URL with correct explicit/template inheritance and no JSON inputs. Explain receive URL and waiting behavior. Existing approved layout is retained.

Tests: valid/persisted/inherited/rejected config; no worker/body consumption on bad password/callback/unknown/pull/LB; exact callback payload, renewal denial/outage, queued stale startup, concurrent publisher conflict, immediate reconnect, disconnect/task drop/stall/worker-stop/delete/auth edits, partial/chunked/malformed packets, upload over 2 MiB, slow producer/backpressure, independent decode to HLS/native M4/RTSP, CPU mode and native source/CDN pulls from publication. Browser field persistence/inheritance/masking and protocol switching. Full Rust/fmt/Clippy/build/browser suite, one fresh whole-branch review and RED/GREEN reported fixes. Qualify isolated owned source/CDN fixtures without touching production Flussonic; audit/package/publish exact verified v0.9 preview and refresh local admin. RTSP publication/push, SRT serving/publishing, direct RTP/SRTP, HTTPS receiving listener, dynamic templates, vendor/full migration and scale remain future gates.
