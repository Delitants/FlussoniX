# Standalone HTTPS v0.10 profile

Implement the first step of secure-output-codecs.md: standalone TLS HTTP output and MPEG-TS publication, preserving the existing qualified H.264/AAC profile. No vendor dependencies; no mandatory TLS proxy. Existing Flussonic production listeners remain untouched.

CLI: optional --https-listen ADDRESS with required --https-cert PEM and --https-key PEM. --https-only requires --https-listen and disables the plaintext HTTP bind; --listen remains the optional plaintext address with its existing default. Validate PEM material using the existing bounded certificate loader and bind all requested sockets before reconciliation starts any worker. The HTTPS TLS profile allows TLS1.2/1.3 and HTTP/1.1. No certificate reload or HTTP/2 claim in this milestone.

HTTPS serves the existing router/app and real socket ConnectInfo: HLS TS/fMP4 manifests, init/segments, continuous TS, M4F signaling/segments, M4S persistent framing, POST publication, management and peer APIs, admin UI. The same viewer/publisher/peer policy checks and worker ownership apply. Untrusted forwarded headers never change client IP or connection security.

The HTTPS acceptor retains at most128 pending handshakes with a five-second handshake deadline, including idle/broken/plaintext clients. Pending futures own sockets and disappear when the listener shuts down; there are no unbounded spawned handshake tasks. Valid arrivals can complete concurrently with slow ones. Established HTTP media uses existing bounded fan-out and graceful shutdown; total connection drain remains five seconds. Do not serialize all users behind a single handshake.

The application records actual bound HTTP/HTTPS addresses and HTTPS-only state without key/certificate bytes or filesystem paths. Expose this status in the authenticated node endpoint and as labeled read-only Config information, with startup-option guidance. Playback/publication URLs use the page's actual origin. HTTPS viewer requests at the LB may select only peers with an explicit valid https public_payload_url; exclude incompatible peers before API admission. HTTP viewers retain existing selection. Auth backend redirects returned to HTTPS viewers must not downgrade to HTTP. Management/private peer addresses stay independent.

Tests use owned CA certificates and ephemeral unused sockets. Prove client trust/identity rejection, TLS-only binding and bad-material/busy-port startup without worker creation, concurrent idle handshakes and cancellation, real callback client IP, forged headers, auth denial/revocation, native wire integrity, HLS decode and HTTPS publication decode. Qualify local/source/CDN/LB secure viewer delivery on isolated ports with the exact binary and without vendor components. Existing lab/private plaintext paths remain permitted; full private-CA HTTP ingest/cluster trust, secure push roles, HEVC/m2a/MP3, certificate reload/expiry UI, SRTP and SRT encryption remain required subsequent profiles.
