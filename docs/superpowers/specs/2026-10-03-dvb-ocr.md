# DVB bitmap subtitles to selectable HLS text

## Intent and scope
Continue the authorized European subtitle conversion stage: native DVB bitmap reconstruction and independent optional OCR produce selectable, authenticated plain-text WebVTT alongside existing 608/708/teletext. Original DVB carriage and HLS pass/convert/filter remain independent. No official Flussonic component/code, production changes or extra source subscription. Existing approved forms are extended rather than redesigned. This is a measured preview profile, not migration readiness.

## Configuration and identities
Each flussonix_hls_captions row selects exactly one of channel1..4, service1..63, teletext_page100..899 or dvb_page0..65535. A DVB row requires ocr_language (one to four plus-separated installed Tesseract model names, each1..24 ASCII alphanumeric/underscore, total<=99); other formats reject that field. Language/name validation and maximum four combined unique selections remain. Service/Cue Rust identities widen to u32: DVB=65536+page, URL dvbN; existing IDs and wire selectors/URLs remain unchanged. OCR options are deployment-only executable FLUSSONIX_TESSERACT (default tesseract), fixed750ms total deadline, at most two simultaneous processes per daemon, minimum mean word confidence60. No API-controlled executable/path. Tesseract and trained language files are optional external dependencies for DVB recognition only.

## Native decoder and transport
Reuse bounded CRC/current first-program single-section PSI/PES transport for both separate subtitle families without weakening teletext tests. DVB descriptor0x59 binds selected composition pages to a unique PID/ancillary page; conflicting advertisements unbind/degrade. PES0xbd with valid PTS and DVB payload0x20 feeds display sets on the existing reordered video frontier. PAT/PMT removal, PID/ancillary replacement, continuity/scrambling/truncation and source reset clear only affected subtitle services; queued stale data cannot survive rebinding.

Independent Rust decoder handles PCS updates/acquisition/mode changes, region/object/palette caches and source PTS timeout/clear. Commit complete display sets at EODS, retaining source PTS across PES fragments; incomplete or unsupported sets clear/degrade instead of OCRing partial images. Support interlaced bitmap objects (coding0), 2/4/8-bit RLE, mapping tables, top-field duplication, non-modifying color, default and explicit full/reduced CLUT luminance/alpha. Object/page/ancillary namespaces remain isolated. Display definition bounds coordinates; exact styling/color/placement are flattened. Character/progressive/compressed objects, alternative/HDR CLUT and disparity are outside initial profile and degrade affected conversion.

Limits: max four selected services;16regions/service;64objects/service;16CLUTs/service;1Mi pixels total region storage/service and rendered crop;2Mi encoded object bytes/service; display metadata<=4096x2304; bounded PES65541, pending64PES/256KiB (existing carrier limits). Reject bounds before allocation. No canvas allocation for unused full display area. End-of-display/clear without recognized text still advances source-clock AV.

## Recognition, timing and failure behavior
Separate asynchronous generation-owned OCR queue holds<=8 images total and<=64 bounded interval records/service. Each image job carries service/token/start/expiry and absolute750ms queue+process deadline. Clear/update/timeout close the previous source interval even while recognition is pending. Historical results may fill their retained interval; canceled/rebound/reset tokens cannot create stale cues. Identical images extend the existing interval without re-recognition. Recognition emits bounded UTF-8 plain text and confidence from TSV; escape at WebVTT rendering. Low confidence, missing executable/model, timeout, oversized output or queue pressure suppress that affected interval and expose reason/confidence in stream stats. Pending intervals bound publication frontier only until their deadline; failures resolve to empty captions and AV resumes. Existing CEA/teletext and other outputs continue. Kill/reap canceled/timed-out processes; stdout/stderr<=64KiB, text<=4096bytes. Monochrome OCR input composites alpha with a contrast-selected background and pads the cropped image.

## UI, qualification and boundaries
Streams/Templates choose DVB bitmap, composition page and OCR model names with friendly fields, inheritance and mixed-format validation. Help explains external language data/confidence/flattened text. Copy and CPU TS/fMP4 HLS delivery use the same private video+subtitle copy feed; all masters/rendition/assets share viewer auth/revocation. Stats report announcement and recognition outcome. Owned literal RLE fixtures and owned rendered English/German words qualify reconstructed pixels, real OCR, exact update/clear/timeout times, missing/slow/failing OCR, independence and real browser text selection with embedded decoding disabled. CI installs independent Tesseract English/German data and font for owned qualification; no vendor binaries. GPU/real HEVC browser/scale/regional relay, automatic discovery, arbitrary programs and enhanced teletext remain pending.

References: ETSI EN300743V1.6.1 (https://www.etsi.org/deliver/etsi_en/300700_300799/300743/01.06.01_60/en_300743v010601p.pdf); Tesseract CLI/TSV (https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html). These define carriage/recognition interfaces; no upstream decoder implementation is copied.
