# Bounded recovery after complete origin blackout

Extend the approved cluster lifecycle so an on-demand CDN pull can restart after temporary unavailability of every configured origin without another viewer request. Preserve vendor independence, verified private transports, local configuration precedence and source equivalence/authority fences. No seamless delivery or production-capacity claim.

Transient unavailability retains the last normalized viewer policy for renewal of already admitted sessions, but exposes no available media route and admits no new viewer through that unavailable route. Explicit disable, known-origin absence, invalid metadata/policy, source removal or policy changes revoke prior authorization as before. Authoritative denial survives subsequent outages. Origin restoration must pass the existing configured-group, content and policy checks.

Recovery demand is derived from the bounded existing authorization cache, not a second ledger. It requires an allowed, available, uncancelled session under the currently published policy, valid token, no active revocation, an unexpired authorization check, and playback activity less than 30 seconds old. Control admissions, denied sessions, historical snapshots and peer-only pulls do not create recovery demand. Background discovery/renewal must never touch playback activity. A restart retains the actual playback timestamp for the media idle clock. Requests after expiry can start media normally.

Reconciliation retains existing worker/static/push behavior and additionally starts discovered mirrors with valid recent demand. Do not create LB encoders. Recheck demand and current available route at the engine startup lock and after asynchronous startup; stop only the exact stale attempt. Config removal/disable, local precedence, policy change and expiry cannot resurrect an old mirror. Existing bounded refresh cadence (10 seconds), query concurrency/budget, ticket/serial and config-revision fences remain.

Qualification must demonstrate a real supervisor stops media while all owned origins are unavailable, then produces fresh native-TLS media after restoration with only read-only node polling. Decode protected HTTP media bound to the observed new generation. Negative coverage pins expiry, control-only activity, revocation, changed policy, authoritative denial, source removal and startup races. Preserve preview credentials/configuration/assets and stop all owned media processes. Run related regressions, full CI and one fresh whole-branch review before GitHub publication and validated preview upgrade.
