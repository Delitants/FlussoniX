Inherited video-dependent fields are cleared when encoder/mode changes; explicit incompatible saved overrides fail validation. A render device must be /dev/dri/renderD followed by1..3 decimal digits; device/mode options require VAAPI encoders. Keep independent video/audio inheritance; copied/CPU/NVIDIA behavior unchanged. Decode in software, format NV12 and upload to selected VAAPI device, one video encoder shared by all output formats. No silent CPU fallback. HEVC8-bit profile only in this increment; 10-bit and hardware decoding remain pending.

Readiness uses the same selected profile as the worker, bounded5seconds and process reaping, keyed/coalesced by encoder/device/low_power; bound retained cache to16 idle/coalesced entries, evict idle entries when full and reject all-in-flight saturation safely. Keep existing NVENC report shape; expose separate default-device vaapi_profiles. Reports are authenticated, sanitized and initialization-only. Media startup checks route ownership after probes, before worker replacement. Existing GPU HLS caption-conversion exclusion remains explicit, with no regression to original subtitle/HLS policies. Friendly codec/device/mode fields and summaries are inherited correctly.

Qualification: configuration rejection/default/inheritance, supervised failure/timeout/reaping/cache and stale-owner preservation; independent actual VAAPI shared-worker delivered H264 through HLS/MPEGTS/native bridge, audio independence and multiple consumers, termination/replacement; independent CPU comparisons. Host HEVC readiness must fail clearly if unsupported rather than be GPU-qualified. Owned extracted iHD/GMM driver only in fixture daemon environment; no host driver install.

## Task2: elementary RTP and SDP

Extend direct RTP options with profile(mp2t default, elementary) and sdp_file(input only, absolute path). Elementary uses plaintext RTP/AVP in this increment; selecting SRTP with elementary fails validation rather than downgrade. Existing encrypted MP2T remains unchanged. Automatic negotiation/DTLS/context transfer remains pending. Native Rust sender reuses existing shared RTSP packetizers: H264,HEVC,AAC-LC,MPEG LayerII/III. One output destination allocates consecutive RTP/RTCP pairs at baseport+2*trackindex, up to8 tracks and4 destination rows. Reserve range through base+15 before enabling elementary output. Interface/multicast/rate fields retain their meaning; include wire overhead in uplink counts.

Input SDP is regular, opened non-symlink, daemon-owned, not group/other writable, bounded16KiB; reject inline keys/crypto, network/file indirection, unsupported payload formats, more than8 media sections, duplicate/overlapping/privileged/out-of-range ports, nonliteral or differing connection addresses, and mismatch of first media port/address with configured input URL. Canonicalize only allowed SDP metadata (media,payload,clock,codec parameters/language); no external fetch. Single validated payload per media section; H264/H265/MPA clocks90kHz, AAC-LC/48000 or supported AAC sample clock with validated AudioSpecificConfig; codec bounds mirror packetizer/decoder support.

Own public RTP/RTCP sockets in Rust, with group-bound multicast isolation, optional source-IP filter, first valid address/SSRC per track, bounded RTP header/payload validation and64-packet reorder. Relay validated full datagrams to exclusively reserved temporary loopback decoder endpoints; only those loopback addresses appear in decoder SDP. Forward valid RTCP only between pinned public media peer and matching local decoder pair; no reflection before pin. FFmpeg's independent SDP depacketizer feeds the existing shared processing/native TS bridge, not a separate transcoder per destination. Shutdown/worker replacement joins all relay/sender tasks and releases public/private ports. Decode SDP is supplied over closed stdin; wait bounded for local decoder binds before forwarding. Input startup/socket preparation does not await media under the global worker lock.

Output publishes actual codec SDP in authenticated runtime status/API for a ready destination, including current track ports and source parameters; UI offers view/download rather than JSON. Sender uses shared packet stream, per-track RTP/RTCP sockets, bounded pacing/sends and generation fences; changed codec metadata fails the destination visibly until new generation rather than issuing stale SDP. Media counts reflect local sends, not receipt. Elementary output carries AV/embedded captions; separate DVB/teletext require MPEG-TS profile. UI labels this distinction.

Qualification: strict SDP/payload parsing and malformed candidate exclusion; source/RTCP isolation, multiple tracks/destinations, unicast IPv4/IPv6 and explicit-interface IPv4 multicast, cancellation/lag/config replacement; independent FFmpeg SDP sender -> shared worker -> native elementary output -> independent decode for H264/HEVC +AAC/MP2/MP3 and audio-only; CPU transcoding plus available internal VAAPI path; existing MP2T/SRTP/caption/cluster behavior via full CI; friendly profile/SDP-reference/download/inheritance browser cases. A short low-resolution qualification is not migration/throughput/WAN certification.
