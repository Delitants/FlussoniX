# RTSP playback preview v0.6

The next approved protocol milestone is outbound RTSP 1.0 playback over TCP-interleaved RTP/RTCP. Existing independent FFmpeg RTSP input remains and is tested against this new output. Full inbound/outbound RTSP/RTSPS/RTP/SRTP, publishing, UDP transport, mixed-vendor interoperability and production-scale qualification remain required future milestones.

## Binding behavior

Optional `--rtsp-listen` starts a dedicated listener; disabled by default. H.264 single NAL/FU-A and AAC-LC MPEG4-GENERIC payloads share one packetizer and bounded fanout per media worker. Metadata validation, timestamps including composition offsets and wrapping, late-join keyframes, AAC fragmentation, and sender reports are exercised with owned media. Unsupported codecs fail RTSP playback without affecting HTTP/native relay. No vendor component or per-client encoder is used.

OPTIONS, DESCRIBE, SETUP, PLAY, GET_PARAMETER and TEARDOWN support FFmpeg TCP playback. PAUSE can return 405 explicitly. UDP/multicast/publish return explicit errors. Bounded control framing rejects ambiguous headers and limits memory. Track/channel/session binding prevents cross-stream and cross-session access. Keepalive/control deadlines, bounded socket writes, lag disconnection and shutdown cleanup bound resource ownership. A reconnect is required after worker replacement or codec changes.

DESCRIBE authorizes the existing URL token/on_play viewer policy with protocol rtsp and peer IP before starting media. Grant cancellation, disabled/deleted/reconfigured streams and stale source selections cannot restart or continue obsolete media. Admission counts include held RTSP grants; worker viewer ownership is RAII. LB HTTP redirect policy is not applied to RTSP: LB-role RTSP playback is unavailable in this preview. CDN RTSP output can pull an authorized private native source using existing discovery.

HTTP egress remains separately measured; RTSP egress is additive and process-mode capacity uses their sum. Interface measurements retain their meaning. UI labels must remain friendly and accurately reflect total media traffic.

Tests run without installed Flussonic. Qualification uses owned synthetic media on isolated unused ports; production Flussonic is never stopped, reconfigured or used for failure injection. Existing authorization to develop, deploy dedicated test copies and publish applies. Preserve preview rollback copies and report actual tested profile and limits.

## Bounds

RTSP control headers 16 KiB, body 64 KiB, incoming interleaved records 8 KiB, <=64 headers, <=256 control connections, eight queued control messages. Initial control/readiness timeout 30/8 seconds, established keepalive 60 seconds, write timeout 2 seconds. Shared RTP queue <=4096 records/16 MiB; bootstrap <=32 MiB and 100000 records, starts at video keyframe; audio-only bootstrap at most two seconds. RTP packets <=1200 bytes. AAC access units <=8191 bytes, fragmented with full AU-size on each packet. H.264 AVCC length widths 1/2/4; up to two unique H.264/AAC tracks. All counters and RTP clocks handle wrapping. Malformed media suppresses the RTSP profile rather than corrupting existing relay.

## Sources

RFC 2326 (RTSP 1.0), RFC 6184 (H.264 RTP), RFC 3640 (AAC MPEG4-GENERIC), RFC 3550 (RTP/RTCP). Implement independently; no copied proprietary implementation.
