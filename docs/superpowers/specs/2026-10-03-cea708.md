# Native CEA-708 to HLS captions

Extend the independent caption pipeline with selected CEA-708 digital services. This follows the approved subtitle design and user instruction to proceed. Existing original pass-through and filtering policies, CEA-608 configuration and URLs, and independent MPEG-TS subtitle policy remain compatible. No Flussonic binaries, source or licensed assets become dependencies.

## Configuration and presentation

`flussonix_hls_captions` accepts up to four unique rows, each containing exactly one of `channel` (CEA-608, 1..4) or `service` (CEA-708, 1..63), plus the existing language and unique display name. Unknown fields and ambiguous selectors fail validation. CC1 and service 1 are distinct. Omitted HLS mode with nonempty rows still implies convert. Inherit/pass/drop retain their existing meanings. Wire JSON never exposes internal numeric service identities.

Friendly stream and template forms select caption format, then channel or service, language and name. Switching format removes the other selector. Template inheritance and validation match the API. Existing CC URLs remain unchanged; digital renditions use `sN.m3u8` and `sN_gGEN_SEQ.vtt`, with stable source-clock cue IDs. All assets share existing viewer authentication and session accounting.

## Decoder contract

New independent Rust decoder accepts raw valid cc_type 2/3 pairs at unwrapped 90kHz source PTS. Selected services only, eight windows per service, bounded 16x42 character grids. Packet size is at most 128 bytes (size zero means 64 words), service blocks at most 31 bytes; extended service IDs supported. Duplicate packets are suppressed, sequence gaps and malformed/truncated packets clear digital display state, never CEA-608 state or AV playback. Pending packet timeout is five source seconds. Unselected service payloads are skipped without interpretation.

Service commands retain bounded partial tokens across blocks. Implement window definition/current selection, clear/display/hide/toggle/delete/reset, pen location, backspace/form feed/carriage return/horizontal carriage return, printable G0/G1/G2/G3 and BMP P16. Parse style and reserved-command parameters without desynchronizing. Support horizontal/vertical print and scroll directions and bounded word wrap. Merge visible windows in anchor order, keeping plain text and line breaks; exact styling, placement, effects and alternate P16 encodings are not qualified.

DLY uses source clock (up to 25.5s), never wall-clock sleeps. DLC cancels immediately; RST cancels/discards pending commands. At most 4096 queued bytes and 512 commands per selected service; overflow clears digital state and reports degraded caption status. Source discontinuities reset both decoder families through the existing transport lifecycle. Existing history, reorder, segment, retention and VTT size bounds remain.

Transport forwards types 2/3 through the existing H.264/HEVC SEI extraction, timestamp unwrapping and B-frame reorder. One upstream connection and private copied video feed serve decoding before CPU transcoding. Caption failure preserves AV playback. Native decoder exposes text changes with service identity and source timestamp; the common cue history feeds both HLS variants.

## Qualification

Hand-authored known packets exercise service isolation, extended IDs, window commands, text sets, partial commands, delay/cancel/reset, malformed packets, sequence gaps, duplicates and limits. Real owned H.264+AAC media carries digital services without a CEA-608 fallback; copy and CPU HLS conversion produce correct selectable WebVTT, timing and quiet tails. TS/fMP4, authentication and original policies retain existing tests. Real browser playback uses external WebVTT with native embedded decoding disabled. An independent primary implementation checks the non-delay fixture; delay timing is tested independently against literal source times.

Final validation: focused tests per task, complete Rust suite, formatting, all-target Clippy, web build and browser suite, one fresh whole-branch review, one tested fix pass, identical-head GitHub CI then authorized fast-forward publication. Teletext conversion and DVB bitmap OCR remain later stages.
