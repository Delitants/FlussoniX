# Selectable live HLS captions: first decoder stage

This architectural stage implements real CEA-608 CC1..CC4 decoding into selectable WebVTT for TS and fMP4 HLS. Existing separate-track preservation remains independent. CEA-708, European teletext conversion, DVB OCR, and full native subtitle relay remain subsequent stages; unavailable conversions are rejected, never advertised as successful.

One FFmpeg input session supplies the existing encode/tee and a private loopback MPEG-TS copy output containing source video before encoding. Rust reads caption SEI in H.264/HEVC, reconstructs PES and unescaped registered T35 data, and runs bounded per-channel 608 display state (pop-on, paint-on, roll-up, row positioning, erase, duplicate controls, parity and basic/special/extended characters). A continuity gap resets the active state. Decoder lag/failure reports an error and private input continues draining so AV delivery cannot block. No independent caption executable or official vendor component is required.

Extension `flussonix_hls_captions` is an array of up to four distinct rows `{channel:1..4, language:ISO-639-code, name:display-name}`. Empty/omitted disables conversion; templates inherit normally. This is not an exact legacy caption API alias. UI offers friendly per-service rows, language and names with explicit template inheritance. Original subtitle track control is unaffected.

Caption state is bounded: TS input/PES <= 2 MiB, at most four 15x32 displays, cue text <= 4096 bytes, at most 4096 completed cues retained for 120 seconds. Video PTS uses 33-bit unwrap; generation replacement clears state. Caption output errors are visible in worker statistics. Enabled caption conversion requires video input; GPU and source clock discontinuities without generation replacement remain unqualified.

HLS entry playlists become masters referencing an AV-only media playlist and subtitle playlists. Names use flat safe filenames, with the existing fmp4 prefix, avoiding ambiguous grouped stream names. All resources reuse current viewer authorization, token rewriting, revocation, TLS and byte accounting. Subtitle segment sequence, duration and discontinuity derive from the AV playlist; every segment exists even during silence. Conversion playlists hold back the newest AV segment, giving caption parsing one segment of headroom. This adds approximately one segment of latency. No subtitle operations block the AV packager.

Use actual first source video PTS and first TS/fMP4 output video presentation timestamps to map clocks; do not assume a fixed mux offset. Capture initial HLS clock anchors while the first segments remain available. WebVTT has a generation-relative local timeline and X-TIMESTAMP-MAP wraps MPEGTS modulo 2^33. Include overlapping cues and current visible display through the segment's end. Safe VTT text escapes markup and never includes source HTML. Cached state/files cannot leak across replacement.

Qualification uses independently authored valid H.264 and HEVC registered caption data, actual known display timing and text, all four channels, repeated controls, Unicode, silence and malformed/oversized inputs. Real copy and CPU workers must publish readable AV and correctly mapped WebVTT without opening a second source connection. API/auth tests require token propagation, denial/revocation on subtitle playlists/segments and grouped stream paths. Browser tests cover inheritance and controls. The installed preview and production servers remain unchanged; publishing follows the already authorized same-head CI and main workflow.

Decision: reject the probed CCExtractor integration for this stage because the pinned release produced start-time errors and no 708 WebVTT on the owned probe. Native 608 is independently verifiable; postponing other decoders costs broader regional conversion coverage but avoids silently mistimed captions.
