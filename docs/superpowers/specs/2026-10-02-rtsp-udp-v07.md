# RTSP unicast UDP playback v0.7

Continue the independent FlussoniX protocol direction matrix. Add RTSP 1.0 controlled unicast RTP/RTCP playback over UDP to the existing authorized H.264/AAC-LC output, source/CDN private pulls and independently installed FFmpeg input adapter. Preserve the v0.6 TCP profile, management/UI contracts and source authority fences. This transport extension is architectural because it adds socket ownership, finite port resources and media pacing.

## Chosen design

Keep packetization shared per worker; use a delivery enum in each negotiated track. A separate bounded UDP module owns a prebound port pool, RAII pair leases and a per-viewer DTS/token-bucket pacer. Reusing packet-level publication or spawning an unconstrained sender per frame would undermine v0.6 buffering and cancellation guarantees. Each RTSP control connection continues owning its grant/viewer accounting, all track sockets and one pending media record. No per-viewer encoding or media dependency is introduced.

UDP is disabled by default. `--rtsp-udp-ports FIRST-LAST` requires `--rtsp-listen`; it is an inclusive, even-first/odd-last range of 2..256 ports, all >=1024. Bind every socket before starting workers, to the RTSP listener IP/family; any occupied port aborts startup without changing other services. Leases retain bound sockets and return them to the same pool on replacement/teardown/EOF/revocation/shutdown. Exhaustion returns 453; TCP remains available. `--rtsp-udp-mbps N` requires the range, finite 1..10000, default 100 per viewer. This limits application RTP datagram payload rate, not Ethernet/IP overhead or packet loss.

Accept `RTP/AVP` and `RTP/AVP/UDP` with explicit `unicast`, consecutive even/odd `client_port` >=1024, and optional PLAY mode. Reject destination/source/server_port/multicast/mux/record/alternatives/duplicate or unknown fields. Bind destinations exclusively to the RTSP control peer's IP, never URI host or requested third-party address. One session uses TCP or UDP, never mixed; overlapping client port pairs or TCP channels across tracks are rejected. Duplicate pre-PLAY SETUP may replace one track without leaking its lease. Response includes client_port, server_port, source and SSRC. No packets are emitted before PLAY or to a denied viewer.

RTP records preserve shared decode timestamps outside wire bytes. UDP sends respect DTS spacing and a 32 KiB token bucket, preventing a saved GOP or fragmented AU from flooding the receiver. Initial/bootstrap and live iteration remain atomic; the existing 4096-batch/64 MiB queue and 32 MiB/100000-packet bootstrap stay bounded. Pending paced packets remain in the session while control/check/cancellation/RTCP futures run; polling another event never loses a media record. Grant/worker/shutdown cancellation interrupts every paced wait and send; datagram sends have a two-second deadline. UDP lag, send error, clock scheduling overflow or a schedule more than 30 seconds ahead closes the session. Queue eviction is inspected on the regular connection tick even during pending waits. TCP wire bytes and timing remain unchanged.

Reserved RTP/RTCP sockets remain unconnected; every send uses the negotiated peer endpoint and received source address is checked explicitly. Wildcard pools determine the advertised source with a temporary same-family route probe. Reused queues must prove empty within 65 bounded raw reads per socket; otherwise that SETUP fails and a retry can continue draining. Incoming RTCP is limited to 8192 bytes, validated for compound framing and RR block sizes/target SSRC before extending keepalive. Wrong endpoint, malformed, stale-target or oversized RTCP is ignored; it cannot authorize, change destinations or bypass grant expiry. UDP receive is owned by the control loop with at most two track sockets; no orphan receive tasks. Sender reports retain shared clocks and actual per-client sent packet/payload counts. Egress/session bytes count successful RTP and RTCP application datagrams; TCP keeps its interleaving overhead. Pool/session/control bounds are safety limits, not scale qualification.

RTSP input arrays accept the documented `rtp: "udp"` setting on `rtsp://` URLs; absence keeps the current TCP adapter. Other protocols, unknown values and keys fail validation. A normal form selector preserves inheritance and clears the option when leaving RTSP. Node telemetry includes UDP application bytes as a subset of total RTSP bytes.

## Acceptance

Parser tests cover both forms, mode, privileged/odd/nonconsecutive/out-of-range ports, duplicate/ambiguous fields and foreign destination rejection. Socket tests prove all-or-nothing binding, exhaustion/reuse, unchanged destinations, malformed/stale/foreign RTCP and lease cleanup. Pacing tests prove DTS and byte-bucket spacing plus cancellation-safe pending delivery. Timed shared records preserve existing RTP bytes and late-join bounds. Real independent FFmpeg UDP clients decode both tracks, including concurrent TCP/UDP viewers sharing one worker, CDN private M4S/M4F output and RTSP UDP input repackaged as HLS. Token/callback denial precedes worker/lease startup; revocation shuts UDP delivery and releases viewer/port ownership. CLI disabled/default/occupied pool and SIGTERM are verified. Existing full Rust, Clippy, web and browser checks pass.

Use unused local ports and only isolated units on cdn4/cdn5; preserve production Flussonic PIDs/listeners/configuration. Qualify the exact static binary with independent clients, including private LAN UDP if available; preserve rollback, no vendor runtime dependency or private credentials in artifacts. Publish v0.7.0-preview only after review, tests and CI; verify downloaded checksums. RTP multicast, ANNOUNCE/RECORD/push, RTSPS, direct RTP/SRTP, Basic/Digest viewer auth, RTSP LB routing, GPU, loss recovery and production scale remain separate gates. UDP playback does not establish all inbound/outbound RTP directions or migration readiness.
