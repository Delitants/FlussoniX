# MPEG-TS worker output decoder foundation

The approved HEVC/MPEG encoding scope requires an independent encoded-output channel: the current worker's FLV native egress supports only AVC/AAC. Implement and qualify a bounded MPEG-TS decoder library first, using the already emitted worker transport and the shared native Track/Frame representation. This source stage does not switch the running worker or advertise new encoding settings. The follow-on integration will remove redundant FLV muxing and connect encoded HEVC/MPEG output to M4F/M4S and RTP.

## Contract

`worker_output::Decoder::push(&[u8]) -> Result<Vec<Event>, String>` consumes arbitrary chunk boundaries; `finish() -> Result<Vec<Event>, String>` flushes the final zero-length video PES and rejects incomplete transport/PES/audio. `Event::Info(Vec<Track>)` precedes `Event::Frame(Frame)`. IDs use transport PIDs. First-program single-section CRC-checked PAT/PMT, up to16 supported AV tracks and at most one video, are qualified. The qualified video profile uses one coded picture per PES, one stable parameter-set family and single-layer HEVC. H.264/HEVC Annex B becomes four-byte length-prefixed access units and real AVC/hvcC parameter-set configuration; AAC-LC ADTS becomes ASC/raw payload; MPEG Layers II/III retain original complete frames and opaque empty configuration. No codec identity is guessed from an audio filename or stream type3 alone.

Limit each caller input chunk to 188*64 bytes, retained transport remainder below188 bytes, PSI to4096 bytes, each PES/sample to16 MiB, total retained media to 32 MiB including pending frame overhead and initialization waiting to 65536 samples, configuration to64 KiB and at most4096 NALs per access unit. Validate continuity/duplicates, adaptation/PES headers, timestamp marker bits, exact audio lengths and stable track/parameter-set layouts. A malformed packet fails the decoder permanently, requiring a new worker generation; no partial access unit is emitted. Unsupported PSI codecs, multi-program/multi-section layouts, scrambling, discontinuities, parameter-set replacement, PCE/SBR AAC, CRC-protected ADTS/multiple raw blocks and incomplete metadata fail explicitly in this initial profile.

Preserve33-bit decode/presentation clocks with shared wrap expansion and signed composition offsets; audio durations use cumulative sample counts at the observed header rate without per-frame rounding drift. Positive/negative B-frame offsets survive. Hold bounded samples until every AV track has validated initialization and publish one complete metadata layout before frames. Each track's DTS stays monotonic; large backwards/discontinuous clocks fail. Ignore null/PCR-only packets; adaptation-only packets do not advance payload continuity. Exact duplicate payload packets are ignored.

## Qualification

Independent worker_ts mux roundtrips compare sample bytes, codecs, DTS and signed PTS; video comparisons account only for removed AUD/repeated parameter-set NALs. Independently produced FFmpeg TS exercises HEVC B-frames, AVC, AAC, both MPEG layers, multiple audio and audio-only. Reconstructed elementary/native remux is decoded and frame/packet identities checked. Malformed/bounded inputs, split/aggregated audio PES, CRC/continuity errors, duplicates and timestamp wrap receive targeted regressions. Existing Rust/browser suites, immutable review and exact-head CI gate source publication. Keep all tests owned/loopback, no installed Flussonic dependency, no production listener changes, and preserve saved preview configuration.

GPU hardware/driver execution, encoding settings, active worker wiring, secure push, mixed-vendor migration, long-duration synchronization and capacity remain follow-on work. The local NVIDIA driver is unavailable, so no GPU claim follows from encoder names alone.

Implementation reference: HEVC configuration field layout and profile-tier-level structure were checked against [FFmpeg 7.1 HEVC configuration source](https://github.com/FFmpeg/FFmpeg/blob/n7.1/libavformat/hevc.c); this decoder is independently implemented Rust and uses owned fixtures. The hvcC header derives observed SPS profile, chroma and bit depth, checks VPS agreement, and leaves optional segmentation/parallelism/frame-rate indications unspecified.
