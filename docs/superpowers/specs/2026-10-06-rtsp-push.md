# RTSP and RTSPS push

User intent: configured Streams and Templates must deliver processed media to other servers over the requested protocols, in both directions, independently of vendor components. Continue the authorized protocol implementation without changing production services or preview configuration.

This architectural addition extends existing bounded push destinations. Use the same `pushes` array, up to four total SRT/RTSP/RTSPS destinations. RTSP entries accept `url`, `disabled`, `comment`, `connect_timeout` (1–30 seconds, default 3), `retry_timeout` (1–300 seconds, default 5), and `flussonix_tls_ca` (absolute regular PEM bundle, RTSPS only). RTSP defaults to port 554; RTSPS to 322. Require nonempty stream path, no userinfo/fragment/controls/whitespace, valid percent encoding, URL at most 4096 bytes. Query data is passed unchanged as receiver credentials; never show paths, queries, CA contents or errors in runtime diagnostics. No insecure TLS switch or downgrade.

Each destination receives the existing bounded shared TS broadcast, uses the existing shared native RTP packetizer and owns one loopback bridge per attempt. The native publisher connects through the owned local bridge. The bridge connects to the configured host, verifies original hostname/IP, certificate validity and roots before forwarding RTSPS data. Rewrite RTSP request authorities to the original destination and preserve path/query/track suffixes. Never follow redirects or accept server-directed transport changes to UDP. Headers, bodies and interleaved frames have bounded buffers. Match response CSeq to at most 16 outstanding requests, validate negotiated distinct channel pairs, count successfully written RTP only after accepted RECORD. Bidirectional RTCP travels on the negotiated channels. Raw protocol errors and subprocess stderr never reach diagnostics.

Require every retained worker TS track to have a supported native RTP mapping; no second encoder, per-destination FFmpeg or silent track omission. Qualification covers H.264 and HEVC with AAC-LC, MPEG Layer II and MP3, plus audio-only. Embedded captions follow worker copy/encode behavior. Separate subtitle tracks have no supported RTSP mapping in this stage; they must fail the destination rather than be silently omitted. Dedicated subtitle transport, Basic/Digest credentials, UDP push and template-created receiving names remain pending. This is a documented v3 pushes subset, not full API or client parity.

Connection/startup deadlines and cancellation encompass DNS/TCP/TLS/protocol setup, process input and network writes. Output media must progress within connect_timeout + 5 seconds initially and ten seconds thereafter; RTCP/control traffic does not reset it. Overflow/failure/stall cancels and joins the native reader and closes the bridge before retry. A broken destination cannot block worker playback or healthy destinations. Disabled entries open no connections or readers. Existing enabled-push on-demand activation, publication waiting, inheritance and generation replacement apply to mixed destinations; mirror discovery never copies local push configuration.

UI extends existing friendly push controls with SRT/RTSP/RTSPS selection, masked RTSP destination URL (query credentials), normal CA/timeouts/enabled fields and sanitized runtime summaries. Preserve SRT forms and template/none semantics. Capabilities and docs accurately separate push from playback and list remaining gaps.

Qualification: real independent FFmpeg receivers and strict per-track decoding, trusted RTSPS and untrusted/wrong-host/expired certificates with no RTSP data forwarded, real receiving-node password success/denial, independent healthy/unreachable outputs, retry/replacement/cancellation, protocol bounds/redirect/transport substitution, desktop/mobile normal forms. Full Rust/browser/fmt/clippy/build and final exact-commit GitHub CI precede preview release. Preserve configuration and credentials byte-for-byte; keep rollback and private evidence; clean only this task's worktree/workspace.
