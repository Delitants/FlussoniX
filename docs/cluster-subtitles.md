# MPEG-TS source pulls with broadcast subtitles

Cluster → Source servers → Source transport now offers **MPEG-TS · broadcast subtitles**. The native source-only extension is `flussonix_transport: "mpegts"`. The existing HLS default and M4F/M4S transports retain their behavior; this is not a legacy Flussonic cluster compatibility claim.

Use the source's private delivery endpoint. HTTP maps to `tshttp://…/stream/mpegts`; HTTPS maps to `tshttps://…/stream/mpegts`. Endpoint prefixes, encoded stream names and query parameters are retained. HTTPS uses the independent Rust HTTP client's normal certificate verification. No insecure TLS switch or additional cluster CA field is introduced.

Set **Original subtitle tracks → Keep original subtitles** on the source and configure its HLS conversion services/pages. Discovery carries those settings to the CDN. MPEG-TS transports the original DVB/teletext descriptors and encoded subtitle PES alongside AV; the CDN reconstructs selected text/OCR renditions using its existing converter. If the source drops original separate tracks, this pull cannot reconstruct them. A ready source WebVTT rendition is not relayed by this transport; OCR/conversion may run on both source and CDN.

The load balancer still authenticates viewers, reserves an eligible CDN and redirects to its public endpoint. The CDN authenticates the viewer before starting one shared worker and one private source subscription. The peer credential remains inside an origin-scoped Rust fetcher; FFmpeg receives only a random loopback URL. Redirects and alternate upstream resources are rejected. The continuous body retains backpressure, one active local request and cancellation; it is not buffered until EOF or subjected to the finite HLS request's total timeout. Each remote read has a ten-second timeout.

Before packager startup, the same source connection supplies at most 1 MiB of initial transport bytes within five seconds. Inspection runs in the stream's supervised startup path; a stalled source does not hold the shared worker-manager lock or delay unrelated streams. The existing bounded CRC-checked PSI assembler identifies the first program's first supported audio stream. The prefix is replayed into the worker without another source subscription. AAC ADTS gets the fMP4 bitstream filter; MPEG audio does not. H.264/AAC and AAC-only copy pulls use a separate FLV copy mux for generated native output, avoiding MPEG-TS codec tags in the common tee. Other generated native codec combinations through this new pull remain unqualified; the existing native M4 copy adapters retain their independently qualified codec support.

Owned Linux qualification uses three real local servers and OS-allocated ports, with copy or CPU encoding at the source and copy at the CDN. The CDN runs as an owned daemon process, giving source and CDN separate daemon-wide OCR budgets as in deployment; source and LB HTTP servers run in the test process. Fixtures are fed on a live sixteen-second clock, rather than bursting an entire programme into the bounded decoder queue. Two Latin teletext languages and two DVB bitmap/OCR languages retain original descriptors and encoded PES. Both CDN HLS variants expose the expected service-isolated text, empty quiet-tail segments and source-relative cue boundaries within one 40 ms video frame. CPU-source fixtures have an observed 21 ms mux/encoder clock offset; zero timing error is not claimed. H.264/AAC and AAC-only native metadata and actual media remain available through M4S. Viewer tokens protect the subtitle assets, and disabling the origin denies cached media after the established source refresh. Generic cluster tests also cover LB admission, multiple viewers sharing one worker and decoded AV.

This does not qualify separate subtitle tracks over M4F/M4S, legacy migration aliases, arbitrary multiplex/program selection, multi-section PSI, GPU conversion, real HEVC browser subtitle output, every source codec combination or sustained production capacity. The caption input keeps its fixed 32-message queue and 16 KiB reads, allowing at most 250 ms for a transient backlog to drain. A persistent stall fails subtitle conversion and closes the optional caption socket while AV continues. Converted subtitle timing continues to use the existing HLS generation grid and bounded OCR deadlines. Source and CDN conversions are distinct; source CPU encoding is not applied again at the CDN.
