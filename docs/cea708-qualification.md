# CEA-708 qualification

FlussoniX converts configured digital services 1..63 to selectable plain-text WebVTT in TS and fMP4 HLS, alongside CC1..CC4. Use Stream/Template → Processing → HLS subtitles → Convert, select CEA-708, a service number, language and display name. Four total distinct renditions are supported. The input must have actual H.264/HEVC video; copy and CPU extraction use the same input connection. GPU conversion and automatic service discovery remain unqualified.

API rows use `{"service":1,"language":"en","name":"English"}`. Existing `channel` rows remain compatible. Digital assets use `s1.m3u8` and generated `s1_g…_….vtt`, share viewer authorization and revoke with the stream policy. Internal decoder identities never appear in configuration or stats.

The native decoder handles selected and extended services, eight windows, definition/visibility/clear/delete/toggle/current selection, pen location, line/backspace controls, G0/G1/G2/G3 and BMP P16, bounded print/scroll directions, horizontal word wrap, source-clock delay/cancel/reset and partial commands. Plain text merges visible windows in anchor order. Exact colors, fonts, layout, effects and alternative P16 encodings are not qualified. Declared columns are bounded to42 and rows to16; reserved G2/G3 use the standard fallback underscore, the enclosed CC mark uses Unicode U+1F16D.

Packet framing/sequence checks clear stale digital display on corruption or gaps. Limits:128 packet bytes, four selected services, eight windows/service,16×42 cells/window,4096 delayed bytes/512 tokens/service,66 partial-token bytes, five source seconds for an unfinished packet. Exceeding a limit resets digital captions with degraded status; AV keeps playing. Existing source discontinuity/PTS unwrap/presentation reorder and shared HLS retention/size limits still apply. Error status remains latched for diagnosis until worker replacement.

Owned16-second H.264/AAC media contains digital services1 and2 and no608 fallback: USA708 and ESPAÑOL display1.16–3.00s; both display LIVE708 at4.12–6.00s, then silence. Copy and CPU worker tests cover both HLS variants, accurate WebVTT boundaries, service isolation, quiet segments, auth/revocation and preservation of separate DVB/teletext on MPEG-TS output. Unit transport tests cover H.264 and HEVC framing and33-bit wrap; real HEVC player delivery remains unqualified.

An independent private qualification ran unmodified [Shaka's packet builder](https://github.com/shaka-project/shaka-player/blob/74a38d2419e29f6b14d2758afec0cd78d2ffa5c7/lib/cea/dtvcc_packet_builder.js), [service](https://github.com/shaka-project/shaka-player/blob/74a38d2419e29f6b14d2758afec0cd78d2ffa5c7/lib/cea/cea708_service.js), window and text utilities at revision74a38d2419e29f6b14d2758afec0cd78d2ffa5c7 over SEI bytes extracted from the generated video. All four words and source-relative display/hide times agreed. Upstream code is research-only, not a production/build/test dependency and is not published in this repository. This oracle covers the fixture's window/text commands; literal source-clock tests qualify delay/cancel separately because this Shaka implementation processes delay commands immediately.

Teletext-to-WebVTT and DVB bitmap OCR remain subsequent decoder stages. Original pass-through/filter controls are unchanged. Exact Flussonic parity and full regional functionality are not claimed.
